# 配置与进阶指南

[返回 README](../README.md)

本页说明 1.6.1 的配置、运行规则、JSON 字段和开发约定。首次使用请先看 README 的快速开始；升级后请重载插件并刷新页面。

## 安装补充

需要 AstrBot **≥ 4.27.0**，当前声明支持的平台适配器为 **aiocqhttp**。

除插件市场外，也可以在插件页上传插件 ZIP，或将插件目录放入 AstrBot 的 data/plugins/ 后重启或重载插件。

## 插件设置

AstrBot WebUI Pages 页面管理本插件的所有配置，任务的增删改查全部在页面完成。不支持在对话中对 bot 发指令管理任务。

插件级配置：

- `log_retention`，默认 100。保留的运行日志条数，最小 10。
- `llm_timeout`，默认 60 秒。单次 AI 生成超时，最小 5。
- `llm_log_retention`，默认 10。LLM 调用记录保留条数，最小 10。LLM调用记录往往体积较大，因此保留不建议太多。

## 任务与触发规则

- **基本信息**：任务名称、启用状态、有效期和发送对象。
- **触发规则**：主动触发器提供时间机会，被动条件决定本次是否执行。
- **任务内容**：执行模式、任务文本、感知开关和对话记录开关。

### 有效期

在基本信息中设置“有效期截止时间”，留空表示不限制。到期后任务自动停用，停用状态会保存；插件启动、调度等待和发送前都会检查有效期。截止时间之前启动的 AI 请求，若在生成完成后已经到期，也不会继续发送。已经开始发送的消息无法通过有效期撤回。

截止时间按浏览器本地时区编辑，保存为 Unix 秒级时间戳。周期、cron、时间区间及提示词中的时间使用 AstrBot 运行环境的本地时区；请留意浏览器与服务器的时区是否一致。

保存一个已到期的任务时，它会保持停用。要恢复执行，需要延长或清空有效期，并重新启用、保存任务。手动“触发一次”也不能绕过有效期。

### 触发器

触发器分主动、被动两类。主动型负责到点唤醒，被动型在唤醒后检查条件。目前支持 6 种：周期、cron、区间、冷却、随机和语境。

主动型有两种：

- **周期型 `interval`**：从基准时间出发，每经过 设定时长 触发一次。与CRON不同，它算的是稳定间隔，设 4 小时 21 分，相邻两次就相差 4 小时 21 分，而不是"每 4 小时的 21 分"。
- **cron 型 `cron`**：标准 5 段表达式，依次是分、时、日、月、周，例如 `0 */4 * * *` 表示每 4 小时。具体请参考CRON语法。

被动型有四种：

- **区间型 `window`**：每天在 start 到 end 之间为真，含端点，也支持 22:00 到次日 06:00 这样的跨天区间。可指定在特定星期运行。
- **冷却型 `cooldown`**：距本任务上次成功的时间达到冷却时长时为真。冷却计时器按任务独立，不能拿一个任务的冷却去约束另一个任务。
- **随机型 `random`**：取随机数小于 threshold 时为真。threshold 为 0 恒假、为 1 恒真；每个实际检查到的随机条件只采样一次，判断与日志使用同一个值。
- **语境型 `contextual`**：独立调用 AI，判断最近的消息是否符合填写的语境要求。判定通过后，才继续执行任务内容。

### 语境条件

添加被动条件后，将类型切换为“语境条件”。各项配置如下：

| 配置 | 行为 |
| --- | --- |
| 语境要求 | 必填，例如“用户最近在讨论学习，适合发送一句鼓励” |
| 上下文条数 | 1–200，默认 20，取最近的消息 |
| 模型提供商 | 默认使用目标对话的 LLM，也可选择其他聊天模型提供商 |
| 模型 | 可选择或输入模型名称，留空使用所选提供商的当前模型 |
| 时间感知 | 默认开启，附加判定时的年月日、星期和时分秒 |
| 节假日感知 | 默认关闭，附加工作日、节假日或调休信息 |

优先读取 AstrBot 已记录的平台消息；没有平台消息记录时，读取当前对话历史中的用户和 assistant 消息。不会主动向聊天平台拉取完整历史。判定使用消息文本，图片、音频等非文本内容以类型占位符表示，不进行媒体内容识别。

用户只需填写语境要求，不需要自行规定返回格式。插件将要求和消息上下文插入固定的 `<scheduled_task>` 提示词，并使用独立的系统提示约束格式。判定请求不注入对话人格或插件请求钩子，不发送用户消息，也不写入对话历史；它与任务生成回复是两次独立请求。

AI 必须仅返回一个合法 JSON 对象，例如：

```json
{"result": true, "reason": "用户最近在讨论学习，符合发送鼓励的语境要求。"}
```

对象只能包含 `result` 和 `reason`：`result` 必须是布尔值，`reason` 必须是非空字符串，长度不超过 100 字。代码块、额外文字、重复字段或不符合类型要求的结果都视为格式错误。没有上下文、读取失败、请求失败、超时或格式错误时，本次跳过，日志区分“判定未通过”与“判定错误”。

两个感知开关独立于任务内容中的同名开关，固定文本任务也可以使用带时间或节假日信息的语境判定。节假日查询失败时省略对应子句，继续判定。

### 组合规则

任一主动型触发，并且所有被动型为真，任务才执行。

配置页面按主动触发器、被动条件分别显示槽位，编号为 A1、A2 和 B1、B2。增删后各组按触发器 ID 升序连续编号；新触发器以创建时的毫秒时间戳作为稳定 ID。可添加多个同类型触发器。主动触发器任一满足、被动条件全部满足后执行任务。

实际检查顺序固定为**区间 → 冷却 → 随机 → 语境**，同类型条件按 ID 升序检查。前项未通过就结束本次检查，返回等待下一次机会；不会在本次机会内反复尝试直到通过。后续未检查项只在原始日志 JSON 中标明，不显示为判定失败。界面的 A/B 编号用于标识条件，不表示跨类型的检查顺序。

多个主动触发器同时到点时，合并为一次检查。“下次任务时间”包含区间和冷却的影响，但不能预测随机与语境判定结果。随机条件的联合概率取乘积，例如两个 50% 条件表示随机通过概率为 25%；含语境条件时还会显示“语境待判定”。到期后的触发时间不再作为未来可执行机会显示。页面每 15 秒刷新一次。

手动“触发一次”跳过全部触发器检查，包括语境条件，只执行任务内容；有效期检查仍生效。验证语境条件是否符合预期，需要观察自动触发的运行日志。

### 任务内容

执行模式决定AI行为：

- **固定文本 `fixed`**：直接将特定文本发给目标，不经过 AI。
- **独立 AI `standalone`**：用任务自己的"独立 AI 系统提示"当 system prompt，再使用任务提示词调用 AI。它不注入对话人格与上下文，也不广播请求钩子。适用于定时任务与bot人格无关，却又需要AI处理的情况。
- **对话 AI `conversation`**：把包裹后的提示词交给目标会话的 AI，会带上该会话的人格、上下文与记忆等插件注入，但不注入 skills 与 tools。适用于需要以bot自己的人格发言的情况。

AI 返回空内容、超时或报错时，该目标记为失败，不会退化成把原文直接发出去。

文本留空是一种特殊配置，称为空动作：任务照常执行、照常记日志，但不发消息，并且会推进冷却计时。可以用它观察触发器是否按预期到点。

### 对话记录

“将回复记入对话记录”默认开启，适用于固定文本、独立 AI 和对话 AI。发送成功后，将实际发出的 bot 消息追加为一条 assistant 消息，供后续对话使用；任务指令和语境判定结果不会作为用户消息写入历史。没有当前对话时，会在发送成功后创建对话用于记录。

关闭这个开关只影响写入：对话 AI 仍会读取目标对话的上下文，独立 AI 仍不读取对话上下文。历史写入失败或超时不会重新发送消息，已成功的发送仍会推进冷却计时，日志单独记录历史写入结果。

### 提示词包裹与感知开关

两种 AI 模式的提示词都会被统一包裹一层，以便于AI区分聊天上下文和计划任务。

```
<scheduled_task>这是由计划任务自动触发的一次会话，现在时间是 2026年09月21日 星期一 20:34:57，今天是工作日。请根据以下指令进行回复。你的回复将被直接发送给用户。<任务提示词></scheduled_task>
```

上面是时间感知与节假日感知都开启的样子。两个开关互相独立：时间感知默认开启，附加"现在时间是"一段，含年月日、周几与时分秒；节假日感知默认关闭，附加"今天是……"一段，需要联网查询。固定文本模式下两个开关都会禁用。

节假日数据取自 timor.tech 的公开接口，成功结果按天缓存，语境判定与任务生成共享缓存。转成的句子分四种：普通工作日是"今天是工作日"，周末是"今天是周六"，调休上班是"今天是工作日，是国庆节后补班"，放假是"今天是中秋节假期"。查询失败时省略该句，任务本身照常执行；失败结果不缓存，因此后续请求仍可能再次查询。

### 发送对象

发送对象是 AstrBot 的 UMO 字符串，格式为 `平台:消息类型:标识`，例如 `default:FriendMessage:xxx`。

页面下拉框列出活跃会话，也可以直接输入 UMO。每个任务只允许一个目标，重新选择会话会替换当前目标。要向不同对话发送，请分别创建任务。

仅在任务文本为空且没有语境条件时，发送对象可以留空。语境条件需要从目标会话读取消息，因此空动作任务包含语境条件时也必须指定发送对象。

在 1.4.x 的旧数据迁移中，`targets` 数组改为单个 `target` 字符串。旧多目标任务只保留数组中的第一个目标，并自动停用、显示“需要重新配置”；编辑保存后才能手动触发或重新启用。旧单目标任务保留启用状态。1.5.1 起不再自动迁移，未迁移的用户请先使用 1.4.3。当前保存接口不接受 `targets` 数组。


## 配置示例

**喝水提醒**：主动周期型每 4 小时一次，配合被动区间型限定 08:00 到 20:00，内容用固定文本"喝水啦~"，这样只在白天发送。

**随机问候**：主动周期型每 2 小时给一次机会，被动区间型限定白天，被动随机型给 50% 命中率，被动冷却型保证两次至少间隔 4 小时。内容用对话 AI，开启时间感知。

**语境鼓励**：周期型每 1 小时检查一次，配合白天时间区间、4 小时冷却和语境条件“用户最近在讨论学习，适合发送一句鼓励”。取最近 20 条消息判定；通过后使用对话 AI 生成鼓励。语境判定与任务生成可分别选择是否附加时间、节假日信息。

**周期+特定时间**：主动周期型每 6 小时一次，再加一个主动 cron 型每天 12:00 一次，则每 6 小时和每天 12:00 都提供触发机会；若添加被动条件，仍须全部满足。

**cron 兼容**：只用一个 cron 型 `30 7 * * *`，每天7:30触发，内容固定文本"早安。"。

**空动作**：文本留空，用来观察触发器是否按预期到点、被动条件是否满足；没有语境条件时发送对象也可以为空。

## 日志与排查

**运行日志**记录触发、跳过、发送、到期停用和故障。列表中的触发情况保留 ✓/✗ 布尔摘要；点击每行末尾的“查看 JSON”，可查看该次运行保存的完整原始信息。弹窗是只读视图，修改当前任务配置不会重建或改变历史记录。

| JSON 字段 | 含义 |
| --- | --- |
| `run_id` | 本次运行标识，关联语境判定与任务生成的 LLM 日志 |
| `trigger_tof` | 实际求值条件的布尔结果；未检查项不放入此字段 |
| `trigger_labels` | 运行当时的 A/B 编号快照 |
| `trigger_details` | 各条件的状态和判断依据，包括冷却间隔、随机采样值、语境理由及错误 |
| `logic_result` | 自动触发的条件组合结果；手动触发或到期停用时可为 `null` |
| `target_result` | 目标、发送结果，以及生成、发送和历史写入的阶段状态；空动作等情况可为 `null` |
| `task_snapshot` | 记录时的任务配置与状态快照 |
| `action` / `detail` / `source` | 动作、说明和来源 |

条件状态包括 `passed`、`rejected`、`error`、`not_checked` 和主动触发器的 `not_fired`。例如随机条件记录 `sample` 与 `threshold`，语境条件记录 `result`、`reason`、`history_source` 和实际上下文条数。运行日志不重复保存完整上下文，完整请求可在 LLM 调用日志中查看。

**LLM 调用日志**分别标记“语境判定”“独立 AI”和“对话 AI”，保存请求、返回、错误与耗时。同一次运行的相关请求共享 `run_id`，语境请求还保存 `trigger_id`。旧版日志可以继续查看 JSON，但不会补造缺失的新字段。

普通判定未通过或执行失败后，任务等待下一个未来机会。配置错误、持久化失败等调度故障会显示“调度故障”，修正问题并保存任务后恢复。发送失败、送达状态未知或发送成功但历史写入失败，都不会自动重发本次消息。


## 任务 JSON 参考

一条任务就是一个 JSON 对象。页面表单和 JSON 模式编辑的是同一份数据，`upsert_task` 接口收的也是它。

```json
{
  "id": "2d7a1fa4-4dd3-49d5-ad36-e95d764ecdbe",
  "name": "随机问候",
  "enabled": true,
  "expires_at": null,
  "triggers": [
    { "id": 1791710000000, "type": "interval", "config": { "base_time": "2026-09-21T00:00", "days": 0, "hours": 2, "minutes": 0 } },
    { "id": 1791710000001, "type": "window", "config": { "start": "08:00", "end": "20:00", "weekdays": [0, 1, 2, 3, 4] } },
    { "id": 1791710000002, "type": "cooldown", "config": { "hours": 4, "minutes": 0 } },
    { "id": 1791710000003, "type": "random", "config": { "threshold": 0.5 } },
    {
      "id": 1791710000004,
      "type": "contextual",
      "config": {
        "requirement": "用户最近在讨论学习，适合发送一句鼓励。",
        "history_count": 20,
        "provider_id": "",
        "model": "",
        "time_aware": true,
        "holiday_aware": false
      }
    }
  ],
  "content": {
    "mode": "conversation",
    "text": "给用户发送一句简短自然的鼓励。",
    "system_prompt": "",
    "time_aware": true,
    "holiday_aware": false,
    "record_history": true
  },
  "target": "default:FriendMessage:xxx"
}
```

顶层字段：

- `id`：任务标识。不带 `id` 表示新增，带 `id` 表示更新对应任务，新建时插件会自动生成。
- `name`：任务名称，必填，最多 32 字符。
- `enabled`：是否启用，默认 true。
- `expires_at`：有效期截止时间，正数 Unix 秒级时间戳；省略或 `null` 表示不限制。到期后自动设置 `enabled: false`。
- `triggers`：触发器数组，至少一个，并且至少要有一个主动型。触发器 id 在任务内唯一，创建后保持稳定；界面的 A/B 编号仅用于显示。
- `content`：任务内容，见下。
- `target`：单个 UMO 字符串。仅文本为空且没有语境条件时可以为空字符串。

`triggers` 每一项由 `id`、`type` 和 `config` 组成，`config` 随类型不同：

- `interval`：`base_time` 是 ISO 格式的基准时间，`days`、`hours`、`minutes` 是周期时长，三者不能同时为 0。
- `cron`：`expr` 是 5 段 cron 表达式。
- `window`：`start` 与 `end` 是 `HH:MM`，`weekdays` 是 0 到 6 的数组（0=周一，6=周日），空数组表示不限定。
- `random`：`threshold` 是 0 到 1 之间的概率。
- `cooldown`：`hours` 与 `minutes` 是冷却时长，不能同时为 0。
- `contextual`：配置字段见下表。至少提供非空的 `requirement`。

语境条件的 `config`：

| 字段 | 类型 / 默认值 | 说明 |
| --- | --- | --- |
| `requirement` | 字符串，必填 | 语境要求；提示词中的文字按原样插入，不支持用户变量替换 |
| `history_count` | 整数，20 | 最近消息条数，范围 1–200 |
| `provider_id` | 字符串，`""` | 留空采用目标对话的聊天模型提供商 |
| `model` | 字符串，`""` | 留空使用上述提供商的当前模型；指定模型仅影响本次请求 |
| `time_aware` | 布尔值，`true` | 语境判定的时间感知 |
| `holiday_aware` | 布尔值，`false` | 语境判定的节假日感知 |

`content` 字段：

- `mode`：`fixed`、`standalone` 或 `conversation`。
- `text`：任务文本，留空即空动作。
- `system_prompt`：仅独立 AI 模式使用，可为空。
- `time_aware`：时间感知开关，仅两种 AI 模式生效。
- `holiday_aware`：节假日感知开关，仅两种 AI 模式生效。
- `record_history`：是否将发送成功的 bot 消息记入对话历史，默认 `true`，对三种模式都生效。

任务上的 `created_at`、`updated_at`、`last_success_time` 和到期停用说明 `disabled_reason` 由插件维护，保存时不必提供；主动触发器不保存 `last_fired`。发送成功时 `last_success_time` 取发送完成时间，空动作时取执行完成时间。

已有的当前格式任务若缺少 `expires_at`，继续按不限有效期运行；缺少 `content.record_history` 时按开启处理。1.5.1 之前未迁移的旧格式任务仍不会自动转换。


## 项目结构

```
astrbot_plugin_enhanced_scheduler/
├── metadata.yaml / _conf_schema.json / requirements.txt
├── scheduler_core.py          # 纯逻辑核心：触发器校验与求值、下次触发计算、合并评估
├── main.py                    # 插件生命周期与 Web API
├── scheduler_runtime.py       # 每任务独立等待、执行互斥与故障状态
├── task_executor.py           # 单目标发送、AI 与会话集成
├── storage.py                 # 任务、运行日志与 LLM 日志存储
```

## 使用边界

- 冷却型依赖本任务的上次成功时间。新任务该值为 0，所以首次触发时冷却恒为真；空动作会推进冷却，跳过与发送失败不会。
- 启动、重载或编辑任务后只等待未来触发点，不补发历史任务；发送失败或超时不自动重发。
- AI 模式不注入 skills 与 tools；对话 AI 的记忆等注入依赖相关插件及请求钩子可用。
- 语境判断仅使用 AstrBot 已记录的消息；平台消息未记录时会退回当前对话历史，不能据此推断已读取聊天平台的全部消息。
- 同一会话内本插件的请求、发送与历史写入串行执行；无法保证正常聊天和其他插件的历史写入与本插件互斥。
- 节假日感知依赖第三方接口，查询失败时该条消息不含节假日子句，并且只支持中国的法定节假日与调休。
